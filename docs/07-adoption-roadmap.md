# 从一个小范围试起

[English](en/07-adoption-roadmap.md) | **简体中文**

先选一个反复出现的问题，试一种改法。不要同时改任务系统、目录、工具和组织，否则很难知道什么起了作用。

| 当前最痛的地方 | 先试什么 | 看什么结果 |
| --- | --- | --- |
| Agent 经常理解错 | 开始前补目标、边界和验收例子。 | 澄清次数与返工是否减少。 |
| 演示通过，上线仍出问题 | 约定完成深度，补真实失败路径。 | 逃逸缺陷与补丁是否减少。 |
| 多人并行却互相等待 | 先定接口，点名阻塞和集成负责人。 | 等待时间与联调返工是否下降。 |
| 旧知识难找、文档互相矛盾 | 区分四类记录，先做只读巡检。 | 找上下文的时间与误报是否下降。 |
| 每次发布都跨团队协调 | 明确领域与共享服务的边界。 | 常规变更能否更独立地交付。 |

试点前记录基线，选风险可控、能获得反馈的任务，指定负责人和复查时间。先积累几个可比较的交付周期；高风险或低频变化需要更长观察，不能用一次成功证明通用有效。

复查只问三件事：结果有没有改善、成本转移到了哪里、哪些步骤可以删除？同时看质量和团队负担，避免只看更快生成或更多关单。

有效的做法进入模板、规则或检查，无效的删掉。扩到下一个领域时重新检查差异。具体起步材料见[记录生命周期](08-record-lifecycle.md)和[任务模板](../templates/task-contract.md)。
