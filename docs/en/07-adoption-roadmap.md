# Start with One Small Trial

**English** | [简体中文](../07-adoption-roadmap.md)

Choose one recurring problem and try one intervention. Changing the task system, directories, tools, and organization together makes it difficult to identify what helped.

| Current difficulty | First intervention | Evidence to watch |
| --- | --- | --- |
| Agents misunderstand work | State the outcome, boundaries, and acceptance examples before implementation. | Clarification and rework. |
| Demos pass but releases fail | Agree on completion depth and test real failure paths. | Escaped defects and patches. |
| Parallel work waits on other tasks | Agree on interfaces and name blocker and integration owners. | Waiting and integration rework. |
| Context is hard to find or contradictory | Separate the four records; start with read-only reporting. | Context-recovery time and false positives. |
| Every release requires cross-team coordination | Clarify domain and shared-service boundaries. | Independent delivery of routine changes. |

Record a baseline, choose work with manageable risk and accessible feedback, and name an owner and review date. Observe several comparable delivery cycles. High-risk or infrequent changes need longer observation; one success does not establish general effectiveness.

Review three questions: did outcomes improve, where did costs move, and which steps can be removed? Include quality and team burden alongside speed.

Put useful practices into templates, rules, or checks; remove ineffective ones. Recheck assumptions when expanding to another domain. Start with the [record lifecycle](08-record-lifecycle.md) or [task template](../../templates/en/task-contract.md).
