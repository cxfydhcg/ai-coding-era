# 记录生命周期政策模板

[English](en/record-lifecycle-policy.md) | **简体中文**

把政策部分复制到仓库已有文档政策中，替换全部方括号值，删除不用的分类，并从助手入口引用。此模板不安装工具。示例和自动化验收见[落地指南](../docs/08-record-lifecycle.md)。

## 政策

- 维护者：[角色或团队]
- 当前行为：[路径]
- 重要变更历史：[路径]
- 长期决策：[已有 ADR 位置，或保留的变更记录]
- 可独立延后工作：[backlog 路径或 tracker]
- 协调的未来工作与完成证据：[需求位置]

一个事实只有一个权威归属。当前文档描述现在；计划明确区分提议、批准和已实现。提升需求时转移证据并删除重复任务。编辑前按路径检索开放项。只在已授权任务边界内修复相邻工作；需要新产品、schema 或跨系统决定的工作继续保留。

## 发布与保留

- 生产证据：[精确 tag 格式或不可变部署记录]
- 排除的证据：[预览、预发布、本地构建]
- 发布时间来源：[部署时间或明确说明的近似值]
- 已勾 backlog：[验证要求，以及清理前需要的发布证据]
- 完成的需求：[包含完成变更的首次发布] 后 [时长]；有门禁或引用时保留。
- 变更记录：[落地或发布] 后 [时长]；保留未解决 fallout 和仍需要的理由。
- 当前文档与长期决策：[复查触发条件]；不按年龄统一删除。
- 证据不可用、格式错误或含糊：保留并报告。

## 门禁与扫描范围

- 源码、原生插件和其他临时代码位置：[路径]
- 必须更新契约文档的变化：[schema、API、权限等]
- 标记语法与解析器：[位置及支持的条件]
- 客户端 rollout 证据与验证负责人：[来源及角色]
- 独立部署依赖的证据：[来源及角色]
- Migration 退役：验证成功应用、新装、受支持备份修复及回滚/支持义务。保留必要修复和 seed。

巡检提出记录维护建议，不删除应用代码、不推断 fleet 版本、不关闭人工门禁。标记到期后，启动一次经过审查的实现任务。

## 日常工作与自动化

- 会话报告：[实际命令，或人工复查]
- 按路径查询 backlog：[实际命令，或搜索步骤]
- 提交前检查：[测试、链接、索引、生成 skill 一致性]
- 不执行 hook 的助手替代步骤：[入口文件及明确步骤]
- 定期报告：[频率和位置]
- 应用模式：[命令，仅在维护分支运行]
- 审查者：[角色]；合并权限：[角色]
- 已验证开 PR 账户和仓库政策：[一次成功的真实维护 PR]
- 自动化不能开 PR 时：[维护者操作步骤]

只列出真实存在的命令。多助手规则保留单一可编辑来源；使用生成副本时，写明副本位置与同步命令。

## 试点验收

- [ ] 新成员能找到当前行为、开放工作和门禁负责人。
- [ ] 测试区分生产与预览证据。
- [ ] 元数据缺失、门禁开放和引用未解决时保留记录。
- [ ] 报告模式只读；应用模式幂等。
- [ ] 扫描范围和本地表格/链接形式有回归测试。
- [ ] 维护 diff 通过文档检查并进入可审查 PR。
- [ ] 记录巡检不删除应用代码。
- [ ] 复查日期：[日期]；证据与政策负责人：[位置及角色]。
